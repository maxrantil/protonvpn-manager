- **Found a DNS leak, filed as #295**: about 1 s after `vpn connect`, NetworkManager
  (`rc-manager=symlink`, regular-file resolv.conf) rewrote `/etc/resolv.conf` with the
  router's `172.20.10.1` and `fe80::…%wlan0`, while openresolv still held `tun0.protonvpn`.
  - Kill switch off: DNS leaks over wlan0, IPv4 **and** IPv6. The IPv6 guard accepts
    `fe80::/10`; verified that the router's link-local address answers.
  - Kill switch on: lookups fail.
  - Fixed for now with `sudo resolvconf -u`. NetworkManager can clobber it again
    (`nmcli general reload dns-full` reproduces it).
- **#294 decision** (commented on the issue): the NetworkManager hook re-adds the server's
  host route. Its PRD comes after #295.
- **PRD** `docs/implementation/PRD-VPN-DNS-PERSISTENCE-2026-11-17.md`, **approved** by
  Doctor Hubert:
  - A: NetworkManager drop-in `rc-manager=resolvconf`
  - B: dispatcher `dns-change` repair branch
  - FR4: `vpn status` warning
  - FR5: stale-entry cleanup
  - FR6: port-53 DNS guard while connected, **on by default**, opt-out `BLOCK_DNS_LEAKS=false`,
    which also blocks link-local DNS
